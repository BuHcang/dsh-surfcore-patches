# 它到底怎么工作

## 1. 为什么是「补丁」而不是「重写插件」

DSH 插件跑在 DSH 的插件宿主里，能拿到工具、提示词、webServer、设置页插槽；
但 SurfCore 是一个**独立的 node 进程**（`node src/bridge.js`），它自己连 OneBot、自己拼提示词、自己管发送队列。

插件宿主和桥进程之间没有共享内存，也没有 RPC 去改「提示词怎么拼」「发送前要不要拆条」这种内部逻辑。
所以有两条路：

- **重写成插件**：等于重做 SurfCore，工作量 10 倍，而且永远落后上游。
- **补丁**：只在上游源码里插几十行钩子，逻辑放在独立模块 `src/custom/*.js` 里，上游升级后重贴。

本项目走第二条。它不管业务，只管「把改动安全地贴回去」。

## 2. 锚点匹配规则

一条补丁的锚点是一段**真实存在的源码文本**（通常是一整行）。匹配顺序：

1. **原文精确匹配**（`indexOf`）；
2. 原文 0 次 → **空白归一匹配**：把连续空白压成一个空格再找，用于上游只改了缩进/换行的情况。

两种方式都要求**恰好命中 1 次**：

- 命中 0 次：上游把这段删了/改了 → 报 `missing`，整批拒绝写入。
- 命中 ≥2 次：锚点太泛（比如只写了一行 `}`）→ 报 `ambiguous`，同样拒绝。

这是刻意的：**静默贴到错误位置**比「贴不上」危险得多。

## 3. 幂等：marker

每条补丁的替换文本里都有一句 `[LOCAL-HOOK <id>]` 注释。
`check` 先看源码里有没有这句：

- 有 → `applied`，跳过（所以一天跑十次 `apply` 也不会贴十遍）；
- 没有 → 继续做锚点匹配。

## 4. 写入顺序与边界

- `copy` 先做（新增模块文件），再按 manifest 顺序做文本补丁；
- 同一文件的补丁**顺序叠加**：前一条改完的文本，是后一条的输入；
- 全部规划成功后才真正写盘：**任何一条失败 → 一个字节都不写**（no partial apply）；
- 每个改过的文件写前都备份到 `backups/<target>-<version>-<时间>/<相对路径>`；
- 写完对每个 `.js` 跑 `node --check`，不通过则报 `syntax-error` 并提示回滚。

## 5. 状态与回滚

`~/.dsh/surfcore-patches/<target>.json` 记录：

```json
{
  "target": "surfcore",
  "version": "0.8.6",
  "at": "2026-11-01T06:42:20.000Z",
  "applied": ["turn-guard/state", "…"],
  "backupDir": "…/backups/surfcore-0.8.6-20261101-144958"
}
```

`revert` = 把 `backupDir` 里的文件原样拷回去。注意：`copy` 新增的文件在备份里可能不存在（之前没有这个文件），所以回滚后它们会留下——这是安全的（多一个未被 import 的模块文件不会影响运行）。

## 6. 版本矩阵

`knownVersions` 是「我验证过锚点能全中的版本」。

- 版本在矩阵里 → 正常 `apply`；
- 不在矩阵里 → `check` 照跑（告诉你会不会全中），但 `apply` 默认拒绝，需要显式 `--allow-unknown`。

升级上游时的标准流程：

```bash
# 1. 先看锚点还在不在
node bin/cli.mjs check --target surfcore --root <新目录>
# 2. 全中 → 加进 knownVersions → apply
# 3. 有 missing → 更新对应 patch 的锚点（把新源码对应行抄过来），再 check
```

## 7. 关于「不打包上游源码」

manifest 里只出现：

- 目标文件名（`src/bridge.js`）、
- 检测用的包名/版本号、
- 每一处定位用的几十字节源码片段。

这些属于「为了定位而引用」，不构成对上游源码的分发。payload 目录里只放**本项目自己写的**模块（`src/custom/*.js`）和为绕开上游模板覆盖而整份提供的**配置文件**（`bili-duty/cordis.patch.yml`，本身就是配置而非代码）。

## 8. 失败时你能看到什么

| 失败 | 返回 | 你能做什么 |
|---|---|---|
| 目标没装 | `code: not-installed` | 在设置里填安装目录 |
| 版本未适配 | `code: unknown-version` | 先 check；确认后 `--allow-unknown` |
| 锚点失效 | `code: anchor-failed` + 每条原因 | 更新 manifest 锚点 |
| 写完语法错 | `code: syntax-error` | 点「回滚」 |

设置页会把每条待贴/异常列出来，不会只写日志。
